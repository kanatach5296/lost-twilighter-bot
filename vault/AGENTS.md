# SecondBrain (Obsidian) エージェント運用ルール (`AGENTS.md`)

このリポジトリ（Vault）は、Obsidianを用いた個人の「第二の脳（SecondBrain）」です。
AIエージェントがノートの作成・編集・整理・検索を行う際は、以下のディレクトリ構成と運用ルールを厳守してください。

---

## 1. フォルダ構成と役割

Vault直下（`SecondBrain/`）の各フォルダは以下の役割を持ちます。ノートの性質に応じて適切なフォルダへ配置・分類してください。

| フォルダ              | 役割・格納するノート    | 備考・配置基準                                                           |
| :---------------- | :------------ | :---------------------------------------------------------------- |
| **`_inbox/`**     | 未整理メモ・一時キャプチャ | 走り書き、分類前のアイデア、Webクリップなどの一時置き場。整理時に適切なフォルダへ移動・昇格させる。               |
| **`Concepts/`**   | 概念・定義・普遍的知識   | 特定の文脈に依存しない「1ノート1概念」のアトミックノート（Evergreen Notes）。用語定義、原則、フレームワークなど。 |
| **`Notes/`**      | 考察・学習・一般ノート   | 複数の概念を組み合わせた考察、記事・書籍の要約、技術メモ、ハウツー、テーマ別のまとめノート（MOC含む）。             |
| **`Projects/`**   | プロジェクト管理・成果物  | 明確なゴールや期限がある取り組みに関する企画書、設計、タスク、進捗記録。                              |
| **`Logs/`**       | 時系列の記録・ログ     | デイリーノート、日報、会議議事録、イベント記録、思考のジャーナルなど日付ベースの記録。                       |
| **`Self/`**       | 自己理解・内省・目標    | 価値観、目標設定（OKR/KPI）、振り返り（KPT等）、キャリアプラン、体調・習慣など自分自身に関するノート。          |
| **`People/`**     | 人物・関係者ノート     | 関わりのある人物のプロフィール、1on1メモ、贈答・会話の記録など。                                |
| **`Docs/`**       | 資料・リファレンス     | 外部仕様書、マニュアル、長文の参考資料、定型ドキュメントなど。                                   |
| **`_templates/`** | テンプレート保管庫     | 各種ノートを新規作成する際のフォーマット定義。                                           |
| **`scripts/`**    | 自動化・補助スクリプト   | Vaultのメンテナンスやデータ処理用のスクリプト群。                                       |

> **注意**: `.obsidian/` や `.copilot/`、`copilot/` などのシステム・プラグイン管理フォルダは、明示的な指示がない限り直接編集しないでください。

## 2. フロントマター（YAML Frontmatter）とタグ付けルール

すべてのノートには、原則としてファイル先頭に **YAMLフロントマター** を付与してください。

### 2.1 標準テンプレート

```yaml
---
created: YYYY-MM-DD
updated: YYYY-MM-DD
type: concept | note | project | log | self | person | doc | inbox
status: seed | growing | evergreen | active | archived
tags:
  - カテゴリ/サブカテゴリ
aliases:
  - 別名・略称
---
```

### 2.2 プロパティのルール
- **`created` / `updated`**: `YYYY-MM-DD` 形式（必要に応じて `YYYY-MM-DD HH:mm`）で記載し、ノート編集時は `updated` を更新する。
- **`type`**: 格納フォルダに対応するノート種別（`concept`, `note`, `project`, `log`, `self`, `person`, `doc`, `inbox`）を明記する。
- **`status`**:
  - 知識系ノート（`Concepts`, `Notes`）: `seed`（種・書きかけ）→ `growing`（育成中）→ `evergreen`（完成度の高い知識）
  - プロジェクト・タスク系（`Projects`）: `planning`（計画中）→ `active`（進行中）→ `completed`（完了） / `archived`（保管）
- **`aliases`**: 表記ゆれ、英語名/日本語名、略称などを登録し、Wikiリンク時の検索性と結合性を高める。

### 2.3 タグ付け（`tags`）ルール
1. **YAMLフロントマター内で一元管理する**:
   - 原則としてタグはフロントマターの `tags:` リストに記載する（YAML内では先頭の `#` を付けない）。
2. **階層タグ（ネスト構造）の活用**:
   - スラッシュ `/` を用いて階層化する（例: `tech/ai`, `project/second-brain`, `area/career`, `book/summary`）。
3. **フォルダとの役割分担**:
   - フォルダは「ノートの種類（Where / What format）」を表し、タグは「横断的なトピック・文脈・状態（Topic / Context）」を表す。
4. **命名の一貫性**:
   - 新規タグを作る前に既存のノートで使われているタグを確認し、同義語の乱立（例: `AI` と `人工知能` の重複など）を防ぐ。英単語は原則小文字ケバブケース（`machine-learning`）または統一された日本語表記を用いる。

## 3. Wikiリンク `[[ ]]` の積極的な活用ルール

Obsidianの最大の強みである「知識のネットワーク化（Graph View / Backlinks）」を最大化するため、以下のルールで **`[[ ]]`（Wikiリンク）を積極的に活用**してください。

1. **文中のキーワードの積極的リンク化**:
   - ノート本文中に重要な概念（`Concepts`）、関連プロジェクト（`Projects`）、人物（`People`）、他ノート（`Notes`）が登場した場合は、積極的に `[[ノート名]]` で囲む。
2. **表示テキストの調整（エイリアスリンク）**:
   - 文脈に合わせて自然な日本語になるよう、`[[正式なノート名|文中の表示テキスト]]` の記法を活用する。
   - 例: `[[Zettelkasten|ツェッテルカステン]]の手法を取り入れる`
3. **未作成ノート（赤リンク）の許容と推奨**:
   - まだファイルが存在しない概念や用語であっても、将来的に重要になりそうなキーワードには積極的に `[[概念名]]` を付けておく（バックリンクが集まった段階で `Concepts/` にノートとして切り出す）。
4. **「関連ノート（Related）」セクションの設置**:
   - ノートの末尾には可能な限り `## 関連ノート` セクションを設け、上位概念・下位概念・類似ノート・参照元ノートへの `[[ ]]` リンクを箇条書きで整理する。
5. **日付・ログとの接続**:
   - 会議録や作業ログ、アイデアが生まれた文脈がある場合は、`[[YYYY-MM-DD]]` の形式でデイリーノートや `Logs/` 内のノートと紐付ける。

---

## 4. ノート作成・整理（Inbox処理・リファクタリング）の原則

1. **1ノート1トピック（アトミック性の維持）**:
   - 特に `Concepts/` や `Notes/` では、1つのノートに複数の独立したテーマを詰め込まない。長大化したノートは概念ごとに分割し、元のノートから `[[分割先ノート]]` へリンクする。
2. **`_inbox/` の整理ワークフロー**:
   - `_inbox/` 内のメモを整理する際は、内容を精査して適切なフォルダ（`Concepts/`, `Notes/`, `Projects/`, `Logs/`, `Self/`, `People/`, `Docs/`）へ移動し、フロントマターと `[[ ]]` リンクを補完する。
   - 既存のノートに統合すべき断片メモは、既存ノートへ追記した上で `_inbox/` から削除（またはアーカイブ）する。
3. **既存知識の探索と接続**:
   - 新しいノートを作成する際は、まずVault内に類似・関連するノートが存在しないか検索し、重複作成を避けるとともに相互に `[[ ]]` でリンクを結ぶ。
4. **可読性の高いMarkdown構造**:
   - 見出し（`##`, `###`）、箇条書き、太字、コールアウト（`> [!NOTE]`, `> [!IMPORTANT]` など）、Mermaid図解などを適切に使い、後から見返した際に一目で要点が掴める構造にする。
